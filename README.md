> 이 저장소는 **비공식 Lumiverse(루미버스) 이식판**이며, **원작자의 허락을 받아** 공개합니다(조건: 원 공유글 링크). 원작에 대한 소유권을 주장하지 않으며, 원작자·Lumiverse·Marinara와 관계가 없습니다. 이 저장소는 원작 저장소의 포크이고, 이식본은 `lumiverse` 브랜치(기본 브랜치)에 있습니다. `main`은 원작 그대로입니다.

긴 RP를 **장면·챕터·사실·미해결 장부**로 정리해 두었다가, 답변 직전에 필요한 기억을 프롬프트에 넣어 주는 확장입니다. 화면에서 기억을 보고 고칠 수 있습니다.

## 설치

Lumiverse의 확장 설치 화면에서 아래 주소를 붙여 넣습니다.

```
https://github.com/mallang0723/marinara-memory-module
```

기본 브랜치가 `lumiverse`라서 브랜치를 따로 고를 필요가 없습니다. 브랜치를 고르는 칸이 있으면 `lumiverse`를 고르세요. 이식본이 아닌 `main`을 고르면 `spindle.json`이 없어 설치되지 않습니다.

설치 뒤 확장을 켜고, 요청하는 권한을 허용합니다(아래 "권한").

> **다른 기억 확장과 함께 쓰지 마세요.** 식별자가 `anon_memory_lv`인 다른 확장(예: 비공개 이식판 LV-AnonMemory의 기억 서재)이나, 같은 `{{memory_ledger}}` 매크로를 쓰는 확장을 같이 켜지 않습니다. 루미버스는 매크로 이름의 두 번째 소유자를 조용히 거절하고, 두 확장이 각자 기억을 정리해 모델 호출이 두 배가 되며, 주입한 기억 블록을 서로 덮어쓸 수 있습니다. **하나만 쓰거나, 다른 쪽의 기억 기능을 끄세요.** 같은 식별자는 한 번에 하나만 설치할 수 있습니다. 확장끼리 서로 있는지 확인하는 방법이 호스트에 없어서 자동 감지는 넣지 않았습니다.

## 설정과 쓰는 법

1. **서랍 탭 `기억 서재`**, 입력창 Extras의 `기억 서재 열기`, Ctrl+K의 `기억 서재 열기`로 화면을 엽니다.
2. 기억 서재 > 설정에서 **`기억 정리에 쓸 연결`**을 고르면 바로 저장됩니다.
3. 기억을 쓰려는 채팅에서 **`기억 사용`**을 켜고 **`이어서 정리`**를 누릅니다. 이후엔 답변이 끝날 때마다 자동으로 갱신됩니다. (서랍 탭의 `이 방 켜기/끄기`, `이어서 정리`, Ctrl+K의 `이 방 기억 이어서 정리`·`이 방 기억 켜기/끄기`도 같은 일을 합니다.)
4. **프롬프트에 들어가는 방법**: 기본은 인터셉터가 채팅 기록 바로 앞에 시스템 메시지 한 개를 넣습니다. 프리셋에 `{{memory_ledger}}` 매크로를 넣어 쓸 수도 있으며, 이미 들어 있는 기억 블록은 **최신 내용으로 교체**되고 두 번 들어가지 않습니다. 매크로 이름이 원작의 `{{기억}}`이 아닌 이유: Lumiverse 매크로 문법은 영문·숫자·`_`·`-`만 이름으로 받습니다.
5. **시간 예산**: 인터셉터는 호스트 기본 10초 안에 끝나야 합니다. 이 확장은 **6초**를 예산으로 잡고(서랍 탭의 `기억 주입에 쓸 수 있는 시간`에서 4·6·8·10초), 모델 회상은 남은 시간이 3초 미만이면 시작하지 않고 원작의 빠른 회상(`fastRecall`)으로 대신합니다. 어떤 오류도 인터셉터 밖으로 던지지 않습니다.
6. 폰에서는 화면 위 닫기 버튼, 뒤로가기(Android back), Esc로 닫습니다(오버레이 닫기 보호). PC에서는 왼쪽 사이드바가 짧은 창에서도 스크롤됩니다.

## 영어로 저장하고 한국어로 보기

기억 서재 → 설정 → **기억 언어**에서 다음처럼 고릅니다. 고르면 바로 저장됩니다.

| 설정 | 권장 값 | 하는 일 |
|---|---|---|
| 기억을 정리할 언어 | **영어로** | 한국어 방도 새 제목·요약·사실·장부를 영어로 저장 |
| 기억을 넣을 언어 | **정리한 언어 그대로(auto)** | 답변 프롬프트에는 영어 기억을 사용. 한국어/영어로 따로 고를 수도 있음 |
| 번역에 쓸 연결 | 기억 정리 연결 그대로 또는 별도 연결 | 서재에 표시할 한국어 번역과 프롬프트용 번역에 사용 |
| 영어 대사도 한국어로 보기 | 필요할 때 켜기 | 화면의 영어 대사 아래에도 한국어 번역 표시 |

영어 기억에는 서재 화면에서 한국어 번역이 함께 표시됩니다. 이름과 원문 인용은 보존합니다. 이전에 한국어로 저장한 기억은 설정 변경만으로 다시 쓰지 않으며, 프롬프트에 넣을 때 번역합니다. 전부 영어로 다시 저장하려는 경우에만 **처음부터 다시 정리**를 사용하세요. 정리 언어의 기본값(auto)은 최근 채팅 언어를 따릅니다.

번역은 줄별로 저장해 재사용합니다. 중간에 실패하면 성공한 번역은 남기고 오류와 남은 개수를 표시합니다. **남은 항목 다시 번역**으로 이어서 처리할 수 있습니다. 내용 제한·잘못된 응답은 묶음을 나누어 재시도하지만 인증·연결·사용량 제한 오류는 나누지 않습니다. 분할 재시도와 식사 의미 비교·대사 상대 확인은 추가 모델 호출을 사용합니다. 모델이 거절한 개별 항목은 원문으로 남습니다.

답변 직전 번역은 인터셉터의 남은 시간 안에서 최대 1초만 기다리며, 나머지는 뒤에서 계속합니다. 설정 변경·방 열기·정리 완료 때 미리 번역하므로 기다리는 동안에도 기존 번역과 원문 기억을 사용할 수 있습니다. 방을 빠르게 바꿔도 이전 방 번역이나 오류가 새 방을 덮어쓰지 않습니다.

## 권한

| 권한 | 쓰는 곳 |
|---|---|
| `generation` | 기억 정리 모델 호출(`generate.quiet`), 연결 목록, 생성 끝 이벤트 |
| `chats` | 채팅 목록·메타데이터 |
| `chat_mutation` | 메시지 읽기(`chat.getMessages`, 읽기만 합니다. 이 권한이 문턱입니다) |
| `characters` | 화자(캐릭터) 이름 |
| `interceptor` | 기억 주입 |

`embeddings`(뜻으로 찾기)는 **요청하지 않습니다.** 구버전 루미버스(1.2.5 등)는 이 권한 이름을 몰라 시작할 때 백엔드가 뜨지 않기 때문입니다. 그래서 뜻 기반 회상(임베딩)은 꺼진 채 나머지 기능이 동작합니다. 설정 화면에 임베딩 항목이 보이지만, 이 권한을 아는 더 새 루미버스와 권한 추가 없이는 쓸 수 없습니다.

서랍 탭·Extras·Ctrl+K·매크로·`userStorage`는 권한이 필요 없는 표면입니다(소스 주석 기준, 실호스트 확인 ⚠️).

## 기억 창 크기

답변 모델이 직접 보는 최신 메시지 수에 맞춰 오래된 대화를 장면으로 접습니다. **루미버스 요약 → 메시지 제한 → 컨텍스트 내 메시지 제한**이 켜져 있고 개수가 유효하면 그 값을 우선합니다. 꺼져 있거나 값을 읽지 못하면 **기억 서재 → 설정 → 모든 방 공통 → 기억 서재 창 크기**를 사용하고, 서재 값도 없으면 **30**을 사용합니다.

설정 화면과 서랍에는 `루미버스 메시지 제한 20 사용 중`, `기억 서재 창 설정 12 사용 중`, `기본 창 크기 30 사용 중`처럼 현재 값과 출처가 표시됩니다. 서재 창 크기를 바꿔도 루미버스의 메시지 제한 설정은 바뀌지 않습니다.

설정은 정리 작업과 답변 직전마다 새로 읽습니다. 현재 Spindle 백엔드에는 일반 사용자 설정 조회 API가 없으므로, 기존 확장 통신으로 열린 프런트엔드에 요청하여 로그인한 사용자의 `/api/v1/settings/summarization`을 읽습니다. **추가 Spindle 권한은 없습니다.** 브라우저가 연결되지 않았거나 세션 인증·조회가 거부되면 최대 1초 뒤 대체값을 사용하며, 사용자별로 확장 실행 중 로그 한 줄만 남깁니다. 별도 API 주소를 쓰는 배포에서 같은 출처의 이 경로가 제공되지 않는 경우에도 대체값을 사용합니다. 실패한 설정값을 저장해 계속 재사용하지 않습니다.

## 저장 위치(모두 `userStorage`, 사용자별)

`memory/settings.json`(연결·회상·방별 켜짐·창 크기·주입 시간) · `memory/chats/<채팅>.json`(장부) · `.scenes.json`(장면·챕터·큰 흐름·사실) · `.vectors.json`(뜻 색인) · `.translations.json`(줄별 번역 캐시, 최대 30,000개) · `.scene-error.txt`. 카드·채팅 메타데이터는 저장소로 쓰지 않습니다. 읽을 수 없는 파일은 `….broken-<시각>`으로 복사해 두고 **덮어쓰지 않습니다**. 이식 전 데이터를 옮기는 코드는 없습니다(새로 시작).

## 원작과 달라진 점

- 원작 서버 패치(`registerHooks`로 Marinara 소스에 한 줄 삽입)·`install.sh`·CLI·`mm`은 가져오지 않았습니다. `service.cjs`는 같은 논리(배치·재시도·반으로 쪼개기·장면/챕터/큰 흐름 순서·회상)로 **다시 썼습니다**(`src/memory/service.js`).
- 원작 코드는 **고쳐 쓰지 않고** 그대로 둡니다. 기억 코어 6개(`src/memory/core/*.cjs`)와 화면 3개(`src/memory/ui/*.orig.*`)는 SHA-256으로 고정돼 있고(`npm run verify:original`), 화면은 빌드할 때 **앵커가 정확히 한 번 일치하는 패치**로만 바뀝니다(0번·2번 이상이면 빌드 실패).
- **원작 기준 커밋**: `3498fd9e267bdb214efe214335245e3b7305ba96`(원작 런타임 0.11.27), 이식판 **1.1.1-lv.1**. 버전별 PORT/SKIP과 **옮기지 않은 것**은 [변경 내역](CHANGELOG.md)에 기록했습니다. 기존 채팅 분기·반복 억제 지침도 유지합니다.
- **분기 이어받기**: Lumiverse가 채팅을 분기하면 보내는 `CHAT_FORKED` 이벤트(권한 불필요)를 받아, 원본의 장부·장면·사실·챕터·큰 흐름·뜻 색인·방별 설정을 새 방으로 복사합니다. 메시지 id와 원문 번호는 새 방 것으로 다시 연결하고, 과거 메시지에서 분기하면 그 뒤 내용은 제외합니다. 새 방에 기억 파일이 이미 있으면 덮어쓰지 않습니다. 원작은 서버 `onSend` 훅이었고 여기서는 이벤트로 대신합니다. 업데이트 전에 만든 분기는 소급하지 않습니다.
- 말풍선 `<speaker>` 태그 복구·생성 지침(Marinara 전용)과 게임 상태 트래커 시계는 없습니다(작중 시간은 본문 날짜 줄만 읽습니다). 라우트 `speaker-tags`는 항상 꺼짐으로 답합니다.
- 수동 메모 파일(`<채팅>.txt`)은 옮기지 않았습니다.
- 채팅 요약은 `chat.metadata.loom_summary` 한 덩어리입니다.
- 모델 JSON 모드(`response_format`)는 먼저 시도하고, 거절되면 그 연결은 빼고 다시 묻습니다.
- 연결·회상·기억 언어 옵션은 **고르는 즉시 저장**됩니다(원작은 저장 버튼).
- 임베딩은 마리나라 연결이 아니라 Lumiverse의 **임베딩 연결**(설정 > 임베딩)을 씁니다(권한이 있을 때).

## 빌드·시험

```bash
BUN_BIN=/path/to/bun npm run build   # 화면 패치 → dist/backend.js, dist/frontend.js (bun 1.4.0)
npm test                            # node --test: 단위 + 원본 테스트
npm run verify:original             # UPSTREAM_MEMORY=<원작 체크아웃>을 주면 원작과도 비교(이 포크의 main이 원작)
npm run qa:browser                  # Firefox + Chromium, 360×460·360×740(터치)·390×844·1280×800, 밝/어두운 호스트 테마
npm run qa:insecure                 # 비보안 출처(http://qa.test)만
```
브라우저 QA는 `PLAYWRIGHT_MODULE`, `FIREFOX_BIN`, `CHROMIUM_BIN` 환경변수가 필요하고, 스크린샷은 `QA_SHOT_DIR`로 갑니다. 모델·외부 네트워크를 부르지 않으며, 보안/비보안 두 출처의 요청을 프로세스 안에서 처리하므로 리스닝 포트도 열지 않습니다. `dist/`는 커밋되어 있어 설치할 때 빌드가 필요 없습니다.

## ⚠️ 한계와 확인하지 못한 것

이 저장소의 시험은 모두 가짜 Spindle 호스트와 브라우저 대역입니다. 아래는 실제 Lumiverse에서 봐야 합니다.

0. **저장소 주소로 설치** — 설치 화면이 기본 브랜치(`lumiverse`)를 받는 동작은 호스트 소스(`git clone --depth 1 [--branch]`)로만 확인했고 실호스트에서 해 보지 못했습니다.
1. **인터셉터 지연** — 실제 모델로 6초 예산이 맞는지, 호스트 사용자 설정이 10초 미만이면 어떤지.
2. **무권한 표면** — 서랍 탭·Extras·Ctrl+K·매크로·`userStorage`가 권한 없이 되는지, Ctrl+K에 서랍 탭 항목과 `열기` 명령이 중복으로 보이는지.
3. **Ctrl+K 방송** — 호스트가 명령 핸들러에 사용자 id를 주지 않아 백엔드가 "명령 X, 채팅 Y"를 모든 접속 프런트에 방송하고, 그 채팅을 보는 화면만 반응합니다. 다인 설치에서는 같은 채팅을 보는 다른 사용자 화면도 반응할 수 있습니다.
4. **모델 JSON 모드** — `generate.quiet`가 `response_format`을 연결 종류별로 어떻게 처리하는지.
5. **메시지 식별** — 원작은 `rowid`, 여기서는 `index_in_chat + 1`과 메시지 `id`+본문 해시입니다. 삭제·브랜치·스와이프 뒤 `reconcile`이 맞는지.
6. **숨김 메시지** — `extra.hidden` 메시지도 읽습니다(이야기의 일부로 봅니다).
7. **그룹 채팅 화자** — `message.name`이 화자 이름으로 믿을 만한지.
8. **채팅 창 크기** — 루미버스 메시지 제한 → 서재 `window` → 기본 30 순으로 선택합니다. 설정 조회에 프런트엔드 연결이 필요하며, 토큰 예산으로 실제 대화가 더 잘리는 경우는 메시지 수 제한만으로 정확하게 재현할 수 없습니다.
9. **저장 규모·지연** — 장면·벡터 JSON이 수 MB가 될 때의 쓰기 시간(`userStorage.write`는 바로 쓰기, 쓰기는 500ms 디바운스).
10. **분기 이벤트 시점** — `CHAT_FORKED`가 첫 답변보다 늦게 오는 경우.
11. **폰(http) 실기기** — 비보안 출처는 보안 API를 지운 브라우저로 흉내 냈습니다. 번들 파싱 시간과 체감은 실기기에서.
12. **번역·음식·대사 상대의 모델 판단** — 실제 모델의 번역 정확도, 음식 동의어 판정과 수신자 판단은 미검증입니다. DeepSeek 등의 추론 설정은 Lumiverse 연결/프리셋에서 관리합니다. 빈 답이 오면 연결의 생각 모드를 확인하세요.
13. **다른 기억 확장과의 동시 설치** — 위 경고대로 쓰지 마세요. 동시에 켰을 때의 정확한 동작은 시험하지 않았습니다.
